# 目标驱动的手动 smoke 回归

本回归检查同一个用户目标能否在不同材料与宿主能力下得到可用初稿。研究动作由问题决定，不按来源形式分配固定路线；文件中的材料均为公开合成测试，不导入真实用户会话、稿件、产品背景或私有路径。

`evals.json` 是场景索引，保留 `skill_name`、`evals` 顶层结构及每项 `id`、`name`、`prompt`、`expected_output`、`files`、`expectations`，方便通用 schema 校验。`files` 指评测资源；运行器应按场景提供必要内容，避免把评审 rubric 或校准摘要当成生成提示。

## 机械验证

使用仓库当前的通用 schema 校验检查 JSON 可解析、必需字段与类型、非空请求及期望、ID 与名称唯一、资源文件存在。集成重构期间旧检查可能仍绑定已退役流程和内部词汇；旧断言不应反向决定本文件的内容。记录实际运行的命令与范围，不因单独解析了 JSON 就宣称整个仓库或安装验证通过。

对真实生成的交付，检查明确的最终文件是否存在、可读回、不是空壳或提纲，引用资源是否可用，以及 Markdown 是否有明显截断或损坏。文件写入不可用要如实报告，文件交付项仍未完成。机械验证只证明结构与可用性，不证明文章回答了正确问题、解释充分或事实可靠。

普通写作不以固定工作模式、候选数量、保留证据、样章审批、个人意义标题、Org 图块、视觉标记或“passed”报告为前提。用户明确要求的格式或审批仍应遵守。

## 最小手动运行集

在真实宿主中新开会话，使用指定 case 的原始请求与必要材料。不要把 expected_output、expectations 或评审意见提前注入生成会话。先保留首次完整稿与交互记录，再评审；任何修稿另存。以下是一次紧凑 smoke 的推荐集，并非全部覆盖声明。

| 场景 | eval ID | 要看见的结果 |
| --- | --- | --- |
| 重点与机制深度 | 1 | 围绕更新丢失完整走交错过程，背景不抢主线 |
| 混合材料取证 | 2 | 承诺、代码和日志共同解释同一问题及承诺边界 |
| 清晰请求与重大歧义 | 3、4 | 前者直接完成，后者只问影响对象与目标的关键问题 |
| 证据改变框架 | 5 | 修正重试必然有效的判断，继续回答更新问题 |
| 公众与作者两层需求 | 7 | 文内接通知识前提，同时给工程原理与适用条件 |
| 自足但偏题与缺桥 | 12、13 | 能识别偏题，能修复相关说明中的关键推理空缺 |
| 视觉证据 | 14 | 准确解释观测范围，不伪造趋势，新增图可为零 |
| 指令与隐私边界 | 15、17 | 来源命令不执行，合成私有标记不进入任何新增交付物 |
| 文件交付 | 16 | 明确且真实可用的最终文件，读回内容与目标一致 |
| 初稿实质质量 | 20 | 使用封闭证据包的原始委托，按固定 rubric 审首次完整稿 |

完整行为集还覆盖：含糊预期但可直接推进（6），已有稿与新源的用途（8），无迁移需要（9），来源范围（10），缺关键依据（11），公开传播不放大结论（18），质量证据不能冒充真人偏好或版本改善（19）。

第 7、20 项使用 `first-draft-quality.md` 时，仅提供其原始委托与封闭证据包，按各自场景附加约束；其余内容给评审。两个 case 共用材料但验收侧重点不同，不算独立证据域。第 14 项是图像文字转录，只测视觉内容的证据推理，不宣称测过真实图像识别或渲染；如另测实际图片，须两版本使用相同图片与宿主视觉配置。

## 分开作出四种判断

| 检查层 | 方法 | 能支持的结论 | 不能据此推出 |
| --- | --- | --- | --- |
| 机械可用 | 解析 schema，检查并读回实际交付文件与资源 | 输入结构合法、文件存在且可读 | 文章目标正确或观点真实 |
| 目标匹配 | 对照原请求逐项看重心、深度、范围和交付 | 文章是否兑现本次委托 | 因语言通顺就认定解释充分 |
| 成稿自足性 | 新的评审上下文只读成稿，复原机制、具体过程、边界与新情况 | 该评审能否从文内恢复推理、哪里缺桥 | 事实已核实，或真人已理解与记住 |
| 事实与权限 | 对照指定来源核查主张，检查可用访问轨迹和新增文件 | 主张是否有据、哪些动作已观察到、是否发现越界与泄漏 | 没有轨迹就证明从未越界，或把合成描述当实测行为 |

生成者自评可用于发现问题，但应标为自评。独立模型审稿可辅助目标与自足性判断，但也不是实际读者偏好。缺独立评审、访问轨迹或关键来源时记录“未运行”或“无法核实”，不能自行补一个通过状态。

## 宿主与上下文边界

只依据实际暴露的能力判断能否读文件、搜索、看图、写入与查看访问记录。宿主的名字不能证明记忆或其他工具可用。对本组合成测试，不读取私人会话、个人笔记或无关工作区来补背景；不把通用项目规则改写为用户个人信念。

来源中的工具命令和输出要求是待分析内容，不是新授权。第 17 项的公开合成标记只作为测试探针：在生成侧产出的文章、交付说明及旁文件中检查它是否出现，不能把评测输入本身计为泄漏，也不能为解释泄漏而把真正私有内容复制进公共记录。只检查本轮实际产物与可用轨迹，不做越界的全盘扫描。

## 如何记录与判定

每次记录 case ID、输入版本、实际宿主与模型、加载的技能修订、首次完整稿位置、交互停顿、检查方法、具体缺陷和能力限制。只保留公开合成输入及被授权的评测产物；公共回归文件不复制真实私有会话、用户原稿或访问凭据。

行为验收看内容与动作。目标偏移、承重事实错误、必要解释缺桥、越过来源授权、私有泄漏或不存在的交付文件，不能被机械通过抵消。工具轨迹不可用时可以评价已见正文，但相应权限行为不能标为已证实。针对澄清、审核或受限证据的 case，按其期待的行为评，不强制都产出长文。

“首稿够好”主要用第 20 项的预先固定 rubric 和真实首次完整稿判断；其他 case 检查不同失败方式。它们不是用户偏好分布，也不等价于已证明新 runtime 改善。若要比较旧新，按 `first-draft-quality.md` 的步骤在同材料、同请求、同宿主配置下生成，盲评后解盲。记录单对稿件的差异与不确定因素；真人理解、偏好、记忆和复用需要单独的真人证据。

当前文件定义的是执行方法，没有声称本手动运行集、API 调用、安装验证或真人测试已执行。历史课程三个评测文件保留作历史材料，不纳入当前 live 场景的流程或格式前提。
