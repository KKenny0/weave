# 特殊审计依据

仅在明确需要审计依据时读取，例如用户要求证明未见证据测试、读取先后顺序、独立上下文恢复，或某项评估明确要求这些证据。普通“核查完整性”、长文初稿、交付报告或机械格式检查不自动触发本协议。先确认所需审计主张，再只执行相关部分，不把所有审计捆绑为默认流程。

## 预留证据与访问顺序

预留测试用于检查暂定 frame 是否能处理构建时未见的证据；它不证明文章自足，也不证明真人理解。选择确实可能改变解释的材料，先明确其身份与预期检验的问题，再在读取之前记录预测。

“未见”必须是真的未读取。若一次抓取已经暴露整篇内容，不能把末章重新命名为 hold-out；已经由主线程、摘要或参与构框的 agent 暴露的材料也不能当未见证据。可以另找独立、未打开的来源；找不到时如实报告没有有效预留测试，不伪造访问状态。

只有需要可追溯记录时才持久化最小审计依据，使用任务允许的审计位置，不往文章目录默认增生附件。记录限于非个人研究主题、候选解释及证据理由、预留来源标识、预先预测和环境获取的时间。不得保存原始委托、用户或团队的目标与偏好、私聊、记忆、读者画像、内部 schema 或研究过程全量笔记。内容限制适用于所有行，字段名称合规不能掩盖私人内容。

写入后回读并清除越界内容，然后才读取预留证据。时间戳只说明记录内容，不能独自证明访问先后；读取顺序需有可核对的工具访问日志或等价记录。没有这种记录就标为顺序未验证，不能凭自写说明补造证明。已暴露之后发现记录无效，只能如实报告或改用真正未读的新证据重新开始。

揭示结果时区分：解释符合预先预测；部分符合且落在原有边界内；在原边界之外失败；看到结果后才修改核心解释。最后一种可以形成更好的研究结论，但不是原预测通过。报告真实失败和如何收缩主张，不把事后修补记成命中。修订后的 frame 若仍需预留验证，必须使用新的未读证据。

## 独立成稿恢复

需要独立恢复依据时，把实际最终文章交给没有参与研究、未见原委托、研究笔记、预期答案和交付报告的新上下文。它可从文章读取文中声明的读者前提；不得用外部材料或原委托帮它填补文章的解释缺口。

让它仅凭文章说明中心模型、机制或依赖关系，走通一个例子，适用时处理一个新情形，指出失效或未决条件，以及任何必须靠文章之外的知识才能跨越的缺口。判断依据是能否恢复并使用承重解释，不能只看复述了多少标题。明确缺口后修订对应段落；只有文章修订后的实际版本接受了复查，才报告该版本的结果。

如果只有同一上下文可用，完成自检并标明独立检查未执行。新建一个角色名、忘记笔记的口头指令或同一会话里的模拟读者不构成独立上下文。普通任务可以交付已经审阅的文章，专门要求独立审计的任务则要说明尚缺的依据。

此检查最多支持 L1 成稿恢复性。L2 真人即时理解、L3 延迟记忆或实际复用分别需要真人观察，不能由 agent 检查推断。审计答案不另存为 sidecar；按用户明确要求仅报告状态、失败维度和相关限制。

## 审计报告与工具

报告限定在所需审计主张：对象文件与版本、实施方法、实际结果、可核对的证据位置、未验证事项和对结论的影响。不把未执行、不可执行或不适用写成 passed，也不因格式检查成功声称语义或时间顺序成立。

运行检查器前查看实际安装版本及参数支持。新版运行检查器接口与兼容约定见 [output-spec.md](output-spec.md)；工具的退出码只反映其实现所覆盖的性质。审计若明确要求机械检查，而工具暂时缺失或仍执行旧规范，就报告该项未验证，不伪造通过，不恢复已取消的流程。
