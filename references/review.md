# 交付前审阅

在需要细化目标匹配、自足性、来源核查或实际文件检查时读取。普通任务在现有上下文与工具条件下完成这些审阅即可，不自动要求 hold-out、独立 agent 或全套审计。仅明确需要审计依据时才读取 [audit.md](audit.md)。

## 目标匹配：看原始委托

重新阅读原始委托和后续修正，再读最终文章，检查：

- 用户明确关注的问题是否得到回答，篇幅和解释深度是否与其重要性相称；标题、关键词或章节存在不算完成解释。
- 整体与局部范围是否被保留；整系统请求是否缩成了最容易读的模块，机制重点是否被长背景淹没。
- 读者前提、深度与产物形式是否符合要求，是否增加了未要求的迁移建议或选择步骤。
- 暂定 frame 是否替用户删掉了难回答的重点；证据若改变了原问题，文章是否解释前提变化及其对原目标的影响。
- 标题与开头承诺是否在正文真正展开，边界是否与结论一致。

修复内容或解释不足，而不是用一句“已覆盖”交代过去。确实无法回答的部分说明具体证据缺口及影响，保留可回答部分的完整解释。

## 自足性：仅凭最终文章

这个检查的输入是最终文章，不从研究笔记、原始委托或记忆中补桥。按文章明确声明的读者前提检查；面向非专业读者可以在开头自然说明假定基础，不能在审阅时临时追加专家前提来使文章过关。

尝试仅由成稿重建中心模型、概念依赖或因果路径，跟完一个承重例子，辨认一个真实的限制条件。文章承诺迁移时，检查它是否提供足够条件让读者判断新情形，而不只是说“可以迁移”。遇到术语、机制跳跃或图中未解释的关系，标出具体位置并补桥。推荐阅读用于延伸，不承担正文已经承诺供应的基础。

源码文章还要能从成稿知道工具解决什么问题、状态与责任如何分布、代表任务怎样流过系统、哪些设计使能力成立且付出什么代价。领域分类要能按相同坐标安放陌生例子，不能将不同抽象层级当互斥类别。

同一上下文已经知道研究过程，要求自己仅凭成稿检查是一种阅读约束，不是清除了背景。结果称为自检，不能称独立新上下文验证。独立恢复检查在明确需要或确有价值且能力可用时实施，协议见 [audit.md](audit.md)，不作为每次初稿的必经步骤。

证据层级仅用于准确报告，不要求逐项收集：研究者重建解释属于生成侧检查；独立新上下文仅凭文章恢复模型是 L1；真人即时无提示复述才可能支持 L2；延迟记忆或实际复用需要 L3 观察。L1 不证明真人理解，点赞、读完和“写得不错”也不证明记住或会用。

## 事实：回到关键依据

逐项复核承重事实、精确引文、数字、比较、因果、版本与当前状态判断。确认引用确实支持邻近主张，标题、作者、URL 和定位一致；别把搜索片段当原文、一个案例当趋势、作者解释当测量结果、结构推断当作者动机。

保留重要反证和来源冲突，核对差异是否来自时间、定义、样本或环境。检查推断和教学构造已标明，推广没有越过证据支持的人群、尺度与条件。易变信息区分发表时、检索时与运行时状态。发布面向公众时同样保留这些限制。

图表逐个检查关系和尺度是否有依据，图注与正文是否一致，视觉单独阅读是否诱导过强结论。没有图不构成缺陷。

对源码运行主张核对实际命令、环境、版本和结果。静态阅读不叫运行验证；测试失败、无法执行或路径未覆盖要具体说明受影响的结论，不能一概写“全部通过”。

## 实际文件：写入后回读

依据 [output-spec.md](output-spec.md) 确认路径和 frontmatter 后，回读磁盘上将交付的文件，必要时分段读完。核对：

- 实际路径、文件名、标题、日期、五个字段和来源列表正确，来源没有无意义重复或占位项。
- 文件保存的是最终修订版本，段落没有截断、重复、临时占位或残留编辑批注；标题承诺与结尾边界仍一致。
- Markdown 围栏、引号、链接、图形与资产引用可用；目标环境的显示限制如实说明。
- 正文、frontmatter、交付报告和同目录附件均未泄露用户 brief、原始私聊、内部 schema、审阅答案或无关私人路径。

可用且与当前规范一致的机械检查器用于检查明确格式性质；它不能证明目标匹配、证据正确或文章好懂。不可用时手动核对并报告限制；旧检查器若仍要求已取消的 schema，应报告规范不兼容，不为过检查向文章补回旧字段或仪式。

## 修复与完成

解释缺桥就补对应段落；重点失衡就删减背景、加深重点；事实失效就回到对应证据并修正下游推断；frame 失效就回到解释主线，同时保持原目标约束。仅重复受修订影响的检查，不固定轮数。

交付前判断初稿是否已经完整且可独立使用：用户最在意的问题有具体解释，机制和例子承重，需迁移时条件明确，结论与不确定性匹配，实际文件与审阅对象相同。仍有关键缺口时明确限定承诺，不能把“请用户再审一遍”当作完成标准。

交付报告只写实际产物、主要结论或覆盖边界、做过的检查及重要未验证项。独立验证未做就不冒称通过；不制造人类审阅 pending 状态来推迟质量责任。对发布、提交和分发保持另行授权边界。
