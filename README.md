<h1 align="center">weave</h1>

<p align="center"><strong>从你想弄明白的问题出发，让证据和取景框共同塑造文章。</strong></p>

<p align="center">简体中文 · <a href="README.en.md">English</a></p>

weave 是一个面向研究与长文写作的 Agent Skill。你可以给它一个问题、一组材料、一个项目，或者正在修改的稿件。它围绕你的目标选择研究动作，形成可修正的解释方向，再写成有依据、重点清楚、适合目标读者的文章。

它的首要质量目标是让**初稿就回应这次委托**：在你真正关心的地方展开，把机制与必要前提讲清，给出有解释作用的例子，并保留证据的边界。完整的流程、很多引用或漂亮的框架名称，都不能代替这些结果。

## 一套主线，按问题决定研究动作

```text
理解原始委托
    ↓
围绕问题研究，补足关键缺口
    ↓
形成并挑战暂定取景框
    ↓
组织解释、写作与局部修订
    ↓
对照委托、证据和实际成稿验收
    └── 有问题，返回受影响的环节
```

weave 不再先按文章、源码或领域分配固定路线。模型可以同时读论文、实现、文档、访谈和实验结果，具体方法由当前问题与证据缺口决定。材料类型只影响局部分析技巧，以及证据允许结论走到哪里。

用户已经说清目标时直接开始。只有不同理解会造成实质不同的范围、重点或交付物，且已有信息无法消歧时，才问一个有影响的问题。没有默认的模式选择问卷、样章批准或强制多轮审稿。

研究不会无限扩张：每次补材料都要针对可能改变核心解释、明确重点或结论边界的缺口。用户限定材料范围时，就在范围内工作。证据不足时说明限制，不用通用知识填补承重事实。

## 取景框怎样服务初稿

取景框是暂定的解释方向，用来判断哪些材料重要、它们之间有什么关系，以及文章应当怎样回答问题。它可以采用来源已有的好解释，也可以是朴素的比较结构；不强制创造新术语或凑出多个候选。

采用一个方向前，weave 会检查它回应了什么问题、改变了哪些取舍、最难解释哪项证据，以及去掉它会损失什么。原始委托、当前研究问题和取景框保持区分：证据可以修正研究问题，取景框可以更换，但不能为了写得顺就悄悄删掉用户明确关心的内容。

写作围绕重点和解释深度分配篇幅。背景只补到足以进入核心问题，术语在需要时解释，具体案例承担推理，迁移判断说明适用条件。图形按解释需要使用；用了就检查关系、箭头与边界，不要求每节配图或采用特殊标记。

## 用法

围绕原理与边界研究：

```text
我想弄懂多个自动化任务同时修改共享资源时，冲突怎样发生、怎样被发现。
请走完一个具体的交错过程，再解释哪些做法能迁移到多人协作系统。
读者懂一点编程，但没有并发控制基础；背景不要盖过核心问题。
```

混合材料：

```text
这里有一篇论文、一份设计文档和一个仓库。
我关心的是它们分别怎样处理失败恢复，而不是分别介绍三份材料。
请核对实现与文档的差别，写成一篇解释机制和代价的文章。
```

已有稿件进入新材料：

```text
这是当前稿件和一篇新文章。先判断新材料是在补事实、改变解释，
还是更适合独立成篇，再处理需要修改的部分。保留已经确定的主问题。
```

只讨论或只读时，按请求返回讨论或分析，不强行生成长文文件。输出语言、篇幅、目录和格式以当前请求为准。

## 怎样验收

weave 分开检查三件事：

| 检查 | 依据 | 要回答的问题 |
| --- | --- | --- |
| 目标匹配 | 原始请求、后续修正、成稿 | 重点、解释深度和读者适配是否兑现？ |
| 文章自足性 | 最终文章及其声明的读者前提 | 核心解释是否完整，有没有必须回查原材料才能补上的桥梁？ |
| 证据与实际产物 | 来源、写入后的文件 | 事实与推断是否分开，边界是否准确，交付文件是否真实可用？ |

模型自检、独立上下文阅读和真人反馈是不同证据，不互相冒充。文件机械检查通过，也不证明文章已经满足委托。需要独立自足性检查时，只用最终文章，不能拿内部研究笔记替正文补桥。

详细审计是按需能力。只有明确检验未读材料的解释能力时才使用 hold-out；没有独立未见材料或访问顺序依据时，不能声称检验或时间顺序已验证。普通的“帮我检查文章”不会自动升级为这一套审计。

## 输出与兼容

新长文默认输出一个 Markdown 文件：

```text
{topic}-weave_{YYYY-MM-DD}.md
```

frontmatter 保留 `title`、`date`、`tags`、`sources` 和 `status`；tags 表达主题，不承担路线分流。文章只保留面向读者的成文，不倾倒内部笔记、用户画像或审计答案。没有实际价值时，不补固定的个人影响章节或零增量说明。

输出目录依次采用：用户指定路径；现有 `.loom/config.yaml` 配置的知识库长文目录；当前工作目录。指定稿件的编辑继续使用该稿件路径。旧文章不重命名、不迁移，已有 vault 配置继续兼容。

普通交付给出实际文件位置、主要结果和重要限制。内容就绪不等于授权提交、发布或分发。

## 安装

通过 [skills CLI](https://github.com/vercel-labs/skills) 安装：

```bash
npx skills add KKenny0/weave --skill weave -g -y
```

需要 Node.js 和 npm。可使用 `-a codex` 或 `-a claude-code` 指定宿主，例如：

```bash
npx skills add KKenny0/weave --skill weave -g -a codex -y
```

本地开发版安装：

```bash
npx skills@1.5.17 add . --skill weave -g -y
```

该命令会更新本机安装；仓库中的自动化安装测试使用隔离目录。历史 `v1.x` 标签保留各自的旧流程；目标驱动主线、默认文件名与检查接口的迁移差异见 [MIGRATION.md](MIGRATION.md)。远端 `main` 的内容不代表本地尚未推送的修改。

如果从 Loom 或旧版 weave 迁移，请阅读 [迁移说明](MIGRATION.md)。旧独立技能的发现冲突需单独处理，不要删除历史稿件来解决安装问题。

## 仓库组织

`SKILL.md` 提供可以直接执行的主线与关键边界。参考文件只在当前任务需要时读取：

| 文件 | 职责 |
| --- | --- |
| [research.md](references/research.md) | 证据获取、定位、冲突、收敛与局部分析技巧 |
| [composition.md](references/composition.md) | 取景、篇章、解释、例子和修订 |
| [review.md](references/review.md) | 目标匹配、自足性、事实与文件验收 |
| [output-spec.md](references/output-spec.md) | 文件、frontmatter、输出目录和交付边界 |
| [audit.md](references/audit.md) | 明确要求时的 hold-out、时间顺序和审计依据 |

`evals/evals.json` 保存结果导向场景，`evals/frame-quality.md` 检查取景框的解释价值，`evals/first-draft-quality.md` 提供封闭合成材料与初稿质量对照方法。历史 Anthropic 课程基线与比较稿保持原样，它们不证明新版初稿已经改善。

## 维护与验证

离线检查和完整检查分别运行：

```powershell
pwsh -NoProfile -File scripts/check.ps1 -SkipInstall
pwsh -NoProfile -File scripts/check.ps1
```

完整检查包含隔离安装与打包内容比对；不会替换本机现役 weave。`-CheckLiveInstall` 额外读取并比较现役安装，不负责更新它。检查会生成并清理自身的临时 fixtures。

检查实际文章，始终优先明确指定文件：

```powershell
pwsh -NoProfile -File scripts/check-article.ps1 -ArticlePath ./文章-weave_2026-11-14.md
pwsh -NoProfile -File scripts/check-run.ps1 -ArticlePath ./文章-weave_2026-11-14.md
```

`check-run.ps1` 保留 `-RunDirectory` 的旧用法，但目录中存在多个可识别文章时必须消歧。显式 `-ArticlePath` 只检查指定文章，不自动关联同目录的旧报告；要一并检查报告时显式传入 `-ReportPath`。`-ImpactMode` 仅用于显式要求的旧格式兼容；新稿不要求固定影响标题。脚本的机械结果不能替代目标匹配、自足性或事实审阅。

真实质量回归应保持同请求、同材料、同宿主配置，比较重点、深度、读者适配、取景框解释价值和证据忠实。缺少对照时，只报告实际完成的验证，不宣称重构已证明普遍提升初稿质量。
