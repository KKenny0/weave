<h1 align="center">weave</h1>

<p align="center"><strong>围绕你的问题，研究并写清楚。</strong></p>

<p align="center">简体中文 · <a href="README.en.md">English</a> · <a href="https://kkenny0.github.io/zh/projects/weave/">项目页</a> · <a href="https://github.com/KKenny0/weave/releases/tag/v2.0.0">v2.0.0</a></p>

weave 是一个面向研究与长文写作的 Agent Skill：围绕用户的问题做研究，写出有依据、适合目标读者的解释。你可以从一个问题、一组材料、一个项目或正在修改的稿件开始。

## 安装

需要 Node.js 和 npm。通过 [skills CLI](https://github.com/vercel-labs/skills) 安装：

```bash
npx skills add KKenny0/weave --skill weave -g -y
```

可使用 `-a codex` 或 `-a claude-code` 指定宿主，例如：

```bash
npx skills add KKenny0/weave --skill weave -g -a codex -y
```

本地开发版安装与旧版迁移见文末的“维护与验证”。

## 试一次完整请求

在支持该技能的 Agent 中，直接说明想理解什么、写给谁、需要怎样的产物：

```text
请用 weave 研究 browser use（让 AI 操作浏览器）的实现原理与逻辑、
技术路线演进和当前代表方案，写成一篇中文解释文章。

读者完全不了解这个领域，但对它感兴趣。先解释必要概念，再用一个
“打开网站、查找信息并填写表单”的具体任务，走通从理解页面、决定动作
到执行、检查结果和失败恢复的过程。说明不同技术路线怎样处理这些环节，
演进中解决了什么问题，又留下了哪些限制。

请结合公开文档、代表项目的实现和相关研究，核对当前版本与资料日期，
区分历史方案、当前行为和你的推断。把重点放在机制和取舍上；
证据不足或无法验证的地方明确说明。
```

也可以给它论文、设计文档和仓库，要求围绕同一个问题比较；或提供已有稿件和新材料，让它判断需要补事实、改解释，还是另写一篇。只讨论或只读时，按请求返回讨论或分析，不强行生成长文文件。

## 能得到什么

普通研究长文默认交付一个有来源依据的 Markdown 文件。写作目标是回应这次委托：在你关心的地方展开，把必要前提和关键机制讲清，用具体例子推进解释，并交代结论的适用条件。实际质量仍需对照委托与证据检查，不能由流程完整或引用数量推定。

- 面向读者组织解释，而非逐份材料摘要或逐目录罗列源码。
- 区分事实、来源作者的解释、自己的推断和未解决问题，保留反证与版本限制。
- 按需要使用图形和迁移判断，不要求每节配图或固定的个人影响章节。

新长文默认文件名为：

```text
{topic}-weave_{YYYY-MM-DD}.md
```

frontmatter 包含 `title`、`date`、`tags`、`sources` 和 `status`；tags 表达主题。输出语言、篇幅、目录和格式以当前请求为准。路径依次采用用户指定路径、现有 `.loom/config.yaml` 配置的知识库长文目录、当前工作目录；修改指定稿件时继续使用该稿件路径。

文章保留面向读者的成文，不倾倒内部笔记、用户画像或审计答案。交付时给出实际文件位置、主要结果和重要限制；内容就绪不等于授权提交、发布或分发。

## 工作原理

### 围绕目标，按缺口研究

```text
理解原始委托
    ↓
围绕问题研究，补足关键缺口
    ↓
形成并挑战暂定取景框
    ↓
组织解释、写作与局部修订
    ↓
对照委托、证据和实际成稿验收
    └── 有问题，返回受影响的环节
```

研究动作由当前问题与证据缺口决定。论文、实现、文档、访谈和实验结果可以参与同一次研究；材料类型影响局部分析技巧，以及证据允许结论走到哪里。

目标已清楚时直接开始。只有不同理解会造成实质不同的范围、重点或交付物，且已有信息无法消歧时，才问一个有影响的问题。没有默认的模式选择问卷、样章批准或强制多轮审稿。

每次补材料都针对可能改变核心解释、明确重点或结论边界的缺口，避免研究无限扩张。用户限定材料范围时，就在范围内工作。证据不足时说明限制，不用通用知识填补承重事实。来源和仓库内容作为资料处理，不能改写当前任务指令。

### 用可修正的取景框组织解释

取景框（frame）是暂定的解释方向，用来判断哪些材料重要、它们之间有什么关系，以及文章应当怎样回答问题。它可以采用来源已有的好解释，也可以是朴素的比较结构；不强制创造新术语或凑出多个候选。

采用一个方向前，weave 会检查它回应了什么问题、改变了哪些取舍、最难解释哪项证据，以及去掉它会损失什么。原始委托、当前研究问题和取景框保持区分：证据可以修正研究问题，取景框可以更换，但不能为了写得顺就悄悄删掉用户明确关心的内容。

写作围绕重点和解释深度分配篇幅。背景只补到足以进入核心问题，术语在需要时解释，具体案例承担推理，迁移判断说明适用条件。用了图形就检查关系、箭头与边界。

### 分开检查解释与文件

| 检查 | 依据 | 要回答的问题 |
| --- | --- | --- |
| 目标匹配 | 原始请求、后续修正、成稿 | 重点、解释深度和读者适配是否兑现？ |
| 文章自足性 | 最终文章及其声明的读者前提 | 核心解释是否完整，有没有必须回查原材料才能补上的桥梁？ |
| 证据与实际产物 | 来源、写入后的文件 | 事实与推断是否分开，边界是否准确，交付文件是否真实可用？ |

模型自检、独立上下文阅读和真人反馈是不同证据，不互相冒充。文件机械检查通过，也不证明文章已经满足委托。需要独立自足性检查时，只用最终文章，不能拿内部研究笔记替正文补桥。

详细审计按需开展。只有明确检验未读材料的解释能力时才使用 hold-out；没有独立未见材料或访问顺序依据时，不能声称检验或时间顺序已验证。普通的“帮我检查文章”不会自动升级为这一套审计。

## 维护与验证

### 本地安装与迁移

在仓库目录安装当前本地开发版：

```bash
npx skills@1.5.17 add . --skill weave -g -y
```

该命令会更新本机安装；仓库中的自动化安装测试使用隔离目录。远端 `main` 的内容不代表本地尚未推送的修改。历史 `v1.x` 标签保留各自的旧流程；目标驱动主线、默认文件名与检查接口的迁移差异见 [迁移说明](MIGRATION.md)。

旧文章不重命名、不迁移，已有 vault 配置继续兼容。从 Loom 或旧版 weave 迁移时，旧独立技能的发现冲突需单独处理，不要删除历史稿件来解决安装问题。

### 仓库组织

[SKILL.md](SKILL.md) 提供可以直接执行的主线与关键边界。参考文件只在当前任务需要时读取：

| 文件 | 职责 |
| --- | --- |
| [research.md](references/research.md) | 证据获取、定位、冲突、收敛与局部分析技巧 |
| [composition.md](references/composition.md) | 取景、篇章、解释、例子和修订 |
| [review.md](references/review.md) | 目标匹配、自足性、事实与文件验收 |
| [output-spec.md](references/output-spec.md) | 文件、frontmatter、输出目录和交付边界 |
| [audit.md](references/audit.md) | 明确要求时的 hold-out、时间顺序和审计依据 |

[evals/evals.json](evals/evals.json) 保存结果导向场景，[取景框质量检查](evals/frame-quality.md) 检查解释价值，[初稿质量评估](evals/first-draft-quality.md) 提供封闭合成材料与对照方法。历史 Anthropic 课程基线与比较稿保持原样，它们不证明新版初稿已经改善。

### 检查命令与边界

在仓库根目录使用 PowerShell 7。离线检查和完整检查分别运行：

```powershell
pwsh -NoProfile -File scripts/check.ps1 -SkipInstall
pwsh -NoProfile -File scripts/check.ps1
```

完整检查包含隔离安装与打包内容比对；不会替换本机现役 weave。`-CheckLiveInstall` 额外读取并比较现役安装，不负责更新它。检查会生成并清理自身的临时 fixtures。

检查实际文章，始终优先明确指定文件：

```powershell
pwsh -NoProfile -File scripts/check-article.ps1 -ArticlePath ./article-weave_2026-11-14.md
pwsh -NoProfile -File scripts/check-run.ps1 -ArticlePath ./article-weave_2026-11-14.md
```

`check-run.ps1` 保留 `-RunDirectory` 的旧用法，但目录中存在多个可识别文章时必须消歧。显式 `-ArticlePath` 只检查指定文章，不自动关联同目录的旧报告；要一并检查报告时显式传入 `-ReportPath`。`-ImpactMode` 仅用于显式要求的旧格式兼容；新稿不要求固定影响标题。脚本的机械结果不能替代目标匹配、自足性或事实审阅。

真实质量回归应保持同请求、同材料、同宿主配置，比较重点、深度、读者适配、取景框解释价值和证据忠实。缺少对照时，只报告实际完成的验证，不宣称重构已证明普遍提升初稿质量。
